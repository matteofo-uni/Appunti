# Tempo minimo degli algoritmi d'ordinamento basati sui confronti
Prendiamo tre numeri generici: $a_1$, $a_2$, $a_3$.

Il comportamento di un qualsiasi algoritmo di ordinamento basato sui confronti può essere ridotto ad un procedimento di questo tipo:
- Confronto $a_1$ e $a_2$:
  - Se $a_1 \leq a_2$, mi faccio delle domande
  - Se $a_1 > a_2$, mi faccio delle altre domande
  
Tutti i percorsi possibli vanno a costituire un **albero**, che in questo caso d'esempio avranno:
- **a sinistra** i casi in cui $a_1$ verrà prima di $a_2$;
- **a destra** i casi in cui $a_1$ verrà dopo di $a_2$.

Ma **quante domande** mi devo fare per raggiungere un vettore ordinato? So che ogni domanda che mi faccio mi permette di dividere l'albero in **due parti**, facendomi **una domanda per livello**, quindi dopo $k$ domande, posso fare **$2^k$ distinzioni** sui dati in input.

Ora mi chiedo in **quante possibili configurazioni** posso trovare i numeri in input. Dato un input di dimensione $n$, ogni numero potrebbe essere in **una qualsiasi** delle $n$ posizioni. Dopo aver posizionato correttamente un numero, mi restano $n - 1$ possibili posizioni, e così via ad ogni iterazione, quindi in totale ho $\prod_{i=1}^{n} i = n!$ **possibili combinazioni**.

Per **garantire** di poter ottenere ogni combinazione valida dei numeri in input, **dev'essere** $2^k \geq n!$, ovvero $k > log_2\space n!$. Andando ad approssimare il valore di $log_2\space n!$, otteniamo che $log_2\space n!$ è dell'ordine $\Theta(n\space log\space n)$, **dunque $k = \Omega(n\space log\space n)$**. 

Ovvero: **per ordinare un vettore con $n$ elementi usando un algoritmo basato sui confronti, devo farmi almeno $n\space log\space n$ domande.** Non è possibile scrivere un algoritmo d'ordinamento **basato sui confronti** (non in generale) che abbia un tempo asintoticamente migliore.

# Counting sort
Il counting sort è algoritmo di ordinamento stabile, non in-loco, e **non basato sul confronto**. 

Questo gli permette di essere più veloce di altri algoritmi di ordinamento, tuttavia solo se il **range di valori in input** è da $1$ a $k$, dove $k = O(n)$.

L'algoritmo utilizza due array di appoggio:
- `b` di dimensione $n$;
- `c` di dimensione $k$, dove $k$ è la "dimensione" del range (ad es. 100 se l'array da ordinare contiene 100 valori distinti)

E funziona in questo modo:
1. **Azzero** tutti i valori di `c`;
2. **Conto quante volte compare ogni elemento dell'input**, memorizzandolo in `c`: ad esempio, se l'input contiene 10 occorrenze del valore 4, `c[4]` avrà come valore 10. 
3. **Somma** in `c` gli elementi da **sinistra verso destra** (`c[i] += c[i - 1]`): questi sono gli indici in cui veranno inseriti gli elementi corrispondenti a `i`. Questo rende **stabile** l'algoritmo;
4. **Scorre** l'array di input **al contrario**, inserendo gli elementi nell'array `b` sulla base dei valori in `c`. Ogni volta che inserisco un valore `i`, **decremento** il valore in `c[i]`.

```cs
void counting_sort(int a[], int b[], int range) {
    // Array di appoggio
    int c[range];

    // 1: Azzero c
    for (int i = 1 to range) {
        c[i] = 0;
    }

    // 2: Conto le frequenze degli elementi
    for (int i = 1 to length(a)) {
        c[a[i]]++;
    }

    // 3: Sommo gli elementi di c da sx a dx
    for (int i = 2 to range) {
        c[i] += c[i - 1];
    }

    // 4: Scorro a ed inserisco in b
    for (int i = length(a) down to 1) {
        int elm = a[i];
        // Trovo la posizione in cui dovrebbe andare elm
        int pos = c[elm];

        b[pos] = a[i];
        // Aggiorno l'indice per la prossima occorrenza di elm
        c[elm]--;
    }
}
```

**Tempo di esecuzione:**
- Tempo generale: $2k + 3n + 2k + 5n = \Theta(n + k)$, dove $k$ è il valore di `range`. Più è ampio il range, meno conviene utilizzare il counting sort!

# Radix sort
Il **radix sort** è una tecnica di ordinamento che viene utilizzata spesso utilizzata per l'**ordinamento alfabetico**.

Utilizza un algoritmo d'ordinamento **stabile** (merge sort, bubble sort, insertion sort, counting sort ecc.), raggruppando i valori ad ogni iterazione partendo **dal simbolo meno significativo a quello più significativo**.

```cs
void radix_sort(key a[], key least, key most) {
    for (key r = least to most) {
        stable_sort(a, r);
    }
}
```

**Tempo di esecuzione:**
- Tempo generale: dipende dal tempo richiesto dall'algoritmo di ordinamento stabile, che viene scelto in base ai soliti criteri. Ad esempio, per l'ordinamento alfabetico, conviene utilizzare il **counting sort**, visto che il range di valori possibili è basso.

# Bucket sort
Il **bucket sort** è un algoritmo di ordinamento in tempo lineare, stabile e non in-loco.<br>
Assume che l'input abbia una **distribuzione uniforme**, nel **range di valori $[0, 1)$**.

L'algoritmo definisce $n$ sottoarray di uguali dimensioni, detti **bucket**, in cui gli $n$ valori in input vengono distribuiti.

```cs
void bucket_sort(float input[], float output[]) {
    // 1. Creo un'array di n liste di float (i bucket)
    list<float> buckets[length(input)];

    // 2. Inserisco a[i] nel bucket n * input[i]
    int count = 1;
    for (i = 1 to length(input)) {
        int bi = (int) (length(input) * input[i]) + 1;
        append(buckets[bi], input[i]);
    }

    // 3. Ordino i bucket individualmente usando l'insertion sort
    for (i = 1 to length(input)) {
        insertion_sort(buckets[i]);
    }

    // 4. Concateno i bucket ordinati
    count = 1;
    for (i = 1 to length(input)) {
        foreach (float f in buckets[i]) {
            output[count++] = f;
        }
    }
}
```
**Tempo di esecuzione:**
- Tempo generale: $2 + 3n + \sum_{i = 1}^{n} O(n_i^2) + 1 + O(n) = O(n) + 3 + \sum_{i = 1}^{n} O(n_i^2)$, dove $n_i$ è il numero di elementi nell'$i$-esimo bucket.
    
    Nonostante ciò, grazie alla distribuzione uniforme dell'input, ogni bucket tenderà ad avere **circa 1 elemento** al suo interno, facendo collassare la sommatoria a $\approx \sum_{i = 1}^{n} O(1) \approx O(n)$.

    L'array finale risulterà ordinato grazie all'originale "smistamento" negli $n$ bucket. Perciò:

- Tempo medio: $\Theta(n)$
